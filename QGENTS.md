# MASTER REFERENCE FOR NEW HTML PROJECTS

## 1. Reference Project

This repository contains a complete HTML educational presentation that serves as the primary technical and visual reference for future projects.

Before creating or modifying a project, inspect the existing reference files, especially:

- `index.html`
- All relevant documentation and supporting files.
- Existing CSS styles, JavaScript functions, components, and interactions.

Do not assume the reference contains only the features mentioned in this guide. Inspect the actual implementation.

## 2. Visual Design

Use the reference project as a standard for:

- Professional visual identity.
- Color palette and typography.
- Backgrounds, gradients, lighting, and visual effects.
- Cards, panels, navigation, and interactive elements.
- Animations and transitions.
- Consistent spacing and visual hierarchy.

Improve the design when the new project requires it. Do not copy weaknesses from the reference.

## 3. Technical Implementation

Reuse appropriate HTML, CSS, and JavaScript patterns.

Preserve useful functionality, including navigation, interactive activities, quizzes, progress indicators, and presentation controls when relevant.

Avoid unnecessary duplication and keep the code modular, readable, and maintainable.

## 4. Responsive Design

Every new project must work correctly on:

- Desktop screens.
- Laptops.
- Tablets.
- Different browser viewport sizes.

Prevent text overflow, overlapping elements, broken layouts, and inaccessible controls.

Support Arabic RTL layouts whenever required.

## 5. Content

The reference project is a design and technical guide, not a source of content to copy.

Use the new project's subject, learning objectives, and supplied materials as the content source.

Never reuse old educational content unless explicitly requested.

## 6. Workflow

Before implementation:

1. Inspect the reference project.
2. Identify reusable design components and functions.
3. Understand the new project's requirements.
4. Propose a suitable structure and implementation plan.

During implementation:

1. Reuse appropriate components.
2. Adapt rather than blindly copy.
3. Preserve existing working functionality.
4. Test responsive behavior and interactive elements.

After implementation:

1. Check the browser layout.
2. Test navigation and controls.
3. Check for console errors.
4. Fix visual and functional defects.

## 7. Protection of Reference Files

Do not overwrite, rename, delete, or substantially modify the original reference files when developing a new project.

Treat the reference as a read-only source unless the user explicitly requests changes.

## 8. Communication

Before major implementation, briefly explain:

- Which reference files were inspected.
- Which components and features will be reused.
- What will be different in the new project.

Do not claim to have inspected or tested anything that was not actually inspected or tested.
